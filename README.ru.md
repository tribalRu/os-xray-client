# os-xray-client

[English](README.md) · **Русский**

Плагин для **OPNsense 26.x**, который запускает **[Xray-core](https://github.com/XTLS/Xray-core)** и управляется из веб-интерфейса.
Добавляете прокси-серверы, решаете, какой трафик куда идёт, а плагин превращает это в конфиг Xray, запускает сервис и следит за ним. Править JSON по SSH не нужно (хотя можно).

Типичный сценарий: домашний или офисный файрвол, который часть трафика отправляет через VLESS / Trojan / WireGuard / WARP-сервер, а остальное пускает напрямую, например *«российские сайты напрямую, всё остальное через прокси»*.

## Что умеет

- **Серверы (исходящие узлы)** — VLESS, VMess, Trojan, Shadowsocks, SOCKS 5, HTTP, WireGuard, Hysteria 2, MASQUE, а также Freedom / Blackhole / DNS / Loopback. Вставьте ссылку `vless://`, `vmess://`, `trojan://`, `ss://` или `hy2://`, и форма заполнится сама.
- **Правила маршрутизации** — понятный список правил, порядок меняется кнопками-стрелками, есть *Pin to top* / *Pin to end*, готовые пресеты (LAN напрямую, РФ напрямую, заблокированное в РФ через прокси, блокировка рекламы, BitTorrent напрямую, блокировка QUIC, всё остальное через прокси) и настраиваемое **Default Action** для трафика, который не подошёл ни под одно правило.
- **GeoData browser** — просмотр содержимого `geosite.dat` / `geoip.dat`, поиск по категориям и записям, вставка в правило; опечатки в тегах `geosite:` / `geoip:` подсвечиваются до Apply.
- **Балансировка** — балансировщики с отказоустойчивостью и стратегиями least-ping / least-load, а также просмотр того, какой узел выбран сейчас.
- **Прозрачная маршрутизация** — Xray сам создаёт нативный TUN-интерфейс; достаточно направить на него шлюз OPNsense и правило файрвола, и целые сегменты LAN пойдут через прокси.
- **Локальные прокси** — необязательные SOCKS5 и HTTP на самом файрволе.
- **Встроенный DNS** — собственный резолвер Xray с разными серверами для разных доменов (например, российские домены на российский резолвер).
- **WARP** — Cloudflare WARP в один клик (WireGuard или MASQUE) и поиск рабочего endpoint для сетей, где стандартный заблокирован.
- **Мониторинг** — проверка задержки узлов, счётчики трафика, живые скорости, виджет на дашборде и просмотр логов.
- **Обслуживание** — обновление Xray-core, GeoIP/GeoSite и самого плагина из интерфейса, с окном прогресса и сообщениями об ошибках.
- **Безопасное применение** — перед перезапуском сервиса сгенерированный конфиг проверяется командой `xray run -test`; при ошибке возвращается предыдущий конфиг.

## Требования

- OPNsense 26.1 или новее (amd64 или aarch64) и root-доступ к ней
- Доступ файрвола в интернет к GitHub (оттуда скачиваются Xray-core, GeoData и обновления)

## Установка

В root-оболочке OPNsense:

```sh
fetch -o /tmp/main.tar.gz https://github.com/tribalRu/os-xray-client/archive/refs/heads/main.tar.gz && tar -xzf /tmp/main.tar.gz -C /tmp && sh /tmp/os-xray-client-main/install.sh
```

Затем откройте **VPN → Xray Client**.

**Обновление:** вкладка *Maintenance* → *Check for Updates*, затем обновите Xray-core, GeoData или сам плагин. Плагин можно поставить и из другой ветки (для тестов; такая ветка помечается как неслитая).

**Удаление:** `sh /tmp/os-xray-client-main/uninstall.sh`. Удаляется только плагин; бинарник Xray, GeoData и `/usr/local/etc/xray/config.json` остаются для будущей переустановки.

## Быстрый старт

1. **Добавьте сервер.** *Outbound Nodes* → **+** → вставьте ссылку (или заполните форму). Серверов может быть несколько, у каждого свой стабильный тег.
2. **Выберите GeoData.** *Maintenance* → *GeoData Source Preset* (например, *Russia (runetfreedom)*) → **Update GeoIP & GeoSite**.
3. **Настройте маршрутизацию.** *Routing → Rules* → **+** → выберите пресет или соберите своё правило. Для «РФ напрямую, остальное через прокси» добавьте пресеты *Bypass Russian domains*, *Bypass Russian IP ranges* и *Everything else → proxy* (в последнем выберите свой сервер как цель). Либо задайте **Default Action** на свой сервер в *Routing → Policy & Sniffing* и перечислите только исключения.
4. **Примените.** Нажмите **Apply & Restart Xray**. Если Xray отклонит конфиг, вы увидите точную ошибку, а прежний конфиг останется на месте.
5. **Направьте трафик в Xray.**
   - *Прозрачный режим (TUN):* включите *Native TUN Inbound* в *General*, примените, назначьте интерфейс `tun_xray0` в *Interfaces → Assignments*, создайте шлюз на `10.255.0.1` **с отключённым мониторингом** и направьте нужный трафик LAN на этот шлюз правилом файрвола (*Firewall → Rules → LAN → Advanced → Gateway*). Оставьте *Domain Sniffing* включённым, иначе доменные правила не сработают.
   - *Режим прокси:* включите локальный SOCKS5 / HTTP и укажите его в настройках клиентов.

## Как работает маршрутизация за две минуты

Xray проверяет правила **сверху вниз** и применяет первое подошедшее. Список в интерфейсе показывает всё, что существует:

```
 (закрыто)  api-in → api                  API статистики, всегда первое
 закреплённые сверху   ...                ваши исключения, которые должны побеждать
 обычные правила       ...                порядок меняется стрелками
 закреплённые в конец  ...                например, «всё остальное → прокси»
 (закрыто)  любой трафик → Default Action всегда последнее (direct, пока не измените)
```

- **Условия внутри одного правила объединяются по «И».** Поэтому пресеты для доменов и для IP — отдельные правила.
- Правило без условий подходит под любой трафик, так что всё ниже него недостижимо. Интерфейс помечает такие правила предупреждением.
- Закрепление работает как плавающие правила в файрволе OPNsense: закреплённое правило держит своё место независимо от номеров остальных.
- Для тегов `geosite:` / `geoip:` нужен набор GeoData, в котором они есть, иначе Xray отклонит конфиг. Помогают проверка тегов в диалоге правила и GeoData browser.

## Обзор вкладок

| Вкладка | Для чего |
| --- | --- |
| **General Settings** | Включение сервиса, TUN, локальные прокси, логи, мониторинг, встроенный DNS |
| **Outbound Nodes** | Ваши серверы, импорт ссылок, задержка и трафик, живые скорости |
| **Routing** | *Rules*, *Balancers*, *Policy & Sniffing* (domain strategy, default action) |
| **DNS Servers** | Серверы и доменные правила DNS для встроенного резолвера |
| **Maintenance** | Версии, обновление Xray-core / GeoData / плагина |
| **Expert Config** | (необязательно) сырые JSON-секции или полный сырой конфиг вместо UI-конструктора |

Редко нужные опции спрятаны за переключателем **Show advanced fields**.

## Если что-то не работает

- **Страницы на клиентах LAN зависают, `access.log` пуст.** Шлюз политики маршрутизации должен быть адресом Xray-конца подсети туннеля (`10.255.0.1` по умолчанию), а не адресом, который OPNsense назначила интерфейсу (`10.255.0.2`). Исправьте в *System → Gateways* и выполните `pfctl -F states`.
- **Apply пишет, что конфиг неверный.** Прочитайте сообщение: чаще всего это тег `geosite:`/`geoip:`, которого нет в установленных GeoData, или удалённый сервер, который всё ещё указан в правиле.
- **Правило ничего не делает.** Проверьте его позицию: выше может стоять включённое правило без условий или правило *Pin to end*, которое срабатывает раньше.
- **Статистика или live selection пусты.** Не отключайте закрытое правило `api-in → api`: именно оно их обслуживает.

Подробности и все опции — в [полном справочнике](docs/REFERENCE.md) (на английском).

## Разработка

Файлы с LF-окончаниями строк (`.gitattributes`). В Windows держите `git config core.fileMode false`, чтобы не терялись биты исполнения у скриптов; `install.sh` заново выставляет `chmod +x` на файрволе. Python-тесты: `python3 src/opnsense/scripts/OPNsense/XrayClient/test_scripts.py`.
